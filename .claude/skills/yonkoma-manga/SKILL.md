# 4コマ漫画づくり（Canva）

公開済みリールの内容を、「事実 → でも → 結論」の4コマ漫画に再構成する。**作成後に簡潔なキャプション案を出すところまでが一連の流れ**（ユーザーに毎回求められる）。

## 0. 前提

- 対象はユーザーが「今日投稿した」と言うリール。日付は会話中の「今日の日付」を使う。
- Canvaツール（`mcp__Canva__*`）は遅延ロード。最初に `ToolSearch` で `select:mcp__Canva__copy-design,mcp__Canva__read-design,mcp__Canva__edit-design,mcp__Canva__generate-image,mcp__Canva__get-generate-image-job` を読み込む。
- ユーザーが構成を指定したらそれを最優先（例：「EVは重いから課税は理解→でも2035年電動車100%→時期尚早では」）。指定がなければ下記の標準構成。

## 1. 元ネタを探す

リールの`caption.txt`はmainにはなく、クラウドルーティンの作業ブランチ（`origin/claude/cool-ptolemy-*`）にあることが多い。

```bash
git fetch origin
for b in $(git branch -r | grep -v HEAD); do
  git ls-tree -r $b --name-only | grep -E "^(Instagram/)?<YYMMDD>" | grep -E "caption|manifest" | sed "s|^|$b: |"
done
git show <branch>:<フォルダ>/caption.txt
git show <branch>:<フォルダ>/media-manifest.txt   # 事実確認の経緯・注意点がある
```

- 同じ日付のリールが複数ある場合は、`git log <branch>`の「公開完了を記録」コミットがある方、またmedia-manifestに「お蔵入り／未公開」とない方を選ぶ。どちらか判断が付かなければ選んだ理由を最後に書く。
- ユーザーが動画を添付した場合は、`ffmpeg -vf "fps=1/5,scale=360:-1,tile=5x2"` でコンタクトシートを作って`Read`で中身を確認する。
- media-manifestに「出典未確認」「全文を読めていない」等の注意書きがあれば、最後の報告で必ず伝える。

## 2. 標準構成

| コマ | 役割 | 内容 |
|---|---|---|
| 1/4 | 事実 | キャプションの核心の数字・出来事。出典が必要なら（朝日新聞の世論調査 等）括弧で添える |
| 2/4 | 事実の詳細 | 大見出しの数字（例：`+1.5%`）＋吹き出しで意味・背景を説明。**30代OLが漫画だけで分かる**ように専門用語を言い換える |
| 3/4 | でも（そうだけど） | 反転・ギャップ。男性が説明し、女性が疑問を口にする（例：「〜なの！？」） |
| 4/4 | 主張＋CTA | 団体の見解（直近の漫画では省略することも多い）＋「保存して、〇〇を見返してね」 |

- 1コマ1情報。キャプションの数字は漫画に全部入れない。省いたものは最後に報告する。
- 数字・固有名詞・日付は`caption.txt`と必ず照合する。決定でなく「調整中」「方針」のものは断定しない（「導入する方向」など）。
- 4コマ目の団体主張：消費税16〜20%・「2つの安心運動」を入れるかは、ユーザーの直近の編集に合わせる。ユーザーが外した版が続いているなら入れず、その旨を報告する。
- 保存CTAは、キャプションにある次の発表日などに合わせる（例：「12月8日の2次速報と見比べてね」）。

## 3. 作り方

1. **複製する**：直近の4コマ漫画（`mcp__Canva__copy-design`）を複製する。キャラクター（男性・女性）、吹き出し、枠、CAFSロゴ、ネイビー×アンバーの配色が引き継がれる。**参考の起点デザイン**：ガソリン補助金の4コマ漫画 `DAHaHuNpbOI` / `DAHaJFRCJAU`（以降は直近の版を複製して連鎖している）。複製元はタイトルを見て直近のものを選ぶ（`mcp__Canva__search-designs`）。ユーザーが編集し直している可能性があるため、複製後に`read-design`で最新の文言・位置を確認する。
2. **編集トランザクションを開く**：`read-design`で`open_transaction:true`、`filter.fields:["thumbnails"]`。`transaction_id`を`edit-design`に渡す。
3. **背景画像**：各ページの大きな背景（`type:rect`で画面ほぼ全面のもの）を`update_fill`で差し替える。新規生成は`generate-image`（`PORTRAIT_4_5`、プロンプトは「フラットなアニメ調、人物・文字・数字なし、ダークネイビー`#0b1420`にアンバー`#d9a441`の差し色、上半分は空ける」）。**生成が`quota_exceeded`なら、過去に生成済みの背景を使い回す**（下の一覧）。使い回したことは必ず報告する。
4. **テキスト差し替え**：`replace_text`→`format_text`（`font_size`）。吹き出しからはみ出したら文字サイズを2〜4px下げる。
5. **確認**：`edit-design`の返す`thumbnail_urls`／画像を毎回見る。行末に1〜2文字だけ落ちる、「〜を」で途切れる、誤字（「府止」「2029度」等）を直す。
6. **保存**：`update_title`で「〇〇の4コマ漫画（YYMMDD）」にし、`finalize:"commit"`。

### 注意

- 画像に**文字・外国語・国旗以外の固有ロゴ・実在人物の顔**を入れない。
- 1コマ目の女性画像に給油機が写る系列は、左を切り取り済み（再編集不要）。
- `edit-design`の`commit`は取り消せない。ユーザーが明示的に「できました／保存して」と言う前提でなくても、4ページ全部を確認してから保存してよい（ユーザーはこれまで毎回そう依頼している）。
- 参考デザインは**書き換えない**。必ず複製して作業する。

## 4. 報告フォーマット

1. 編集用・閲覧用URLとタイトル
2. 4コマの構成表（コマ／役割／内容）
3. 「数字はキャプションと照らし合わせた」旨
4. **ご確認いただきたい点**：背景の使い回し（どのコマが過去のどの漫画と同じか）、漫画に入れなかった数字、団体主張・「2つの安心運動」を入れていないこと、断定を避けた表現、元記事の出典の弱さ
5. 作業中に直した誤字があれば一言
6. 「キャプション案も作りましょうか」と一言添える

## 5. キャプション案（簡潔版）

ユーザーが「キャプション案も」と言ったら、**ユーザーが編集し直している可能性があるので、まず`read-design`で最新の4コマの文言を読み直す**（元の設計とずれていたら、編集後の漫画に合わせる）。

- 構成は4コマの流れに沿って段落を4つ前後に（事実 → でも → 主張・まとめ → 保存の呼びかけとコメントのお願い）。
- 出典は数字の根拠になる主要なもの2〜3件に絞る。元のキャプションとの差分（省いたもの）を最後に箇条書きで示す。
- 音楽クレジット（Kevin MacLeod）はリール専用なので入れない。
- ハッシュタグは8〜12個。末尾に`#財政健全化を求める市民の会`。
- 団体の主張（消費税16〜20%、2つの安心運動）は、編集後の4コマ目にある場合だけ入れる。外れていれば入れず、入れる場合の1文を代替案として添える。
- 出典の弱い数字・断定できない点は「判断が分かれる点／確認したい点」として最後に列挙する。
